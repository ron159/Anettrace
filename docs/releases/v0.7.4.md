# Anettrace v0.7.4

## 主要变化

- 修复 Perfetto 紧凑模式显式使用 `--trace tcp` 或 `--trace udp` 时，负载收发正常却缺少 `TCP packet send` / `UDP packet send` 事件和发送 flow 标记的问题。
- 为传输层发送探针补齐 IP 输出探针依赖，保证事件使用完整的 IP 包头；保留显式探针排除规则及连接诊断模式的配置。
- 新增实际 TCP/UDP 回环数据收发测试，覆盖默认配置、显式分组和发送/接收 flow 标记。

## 快速使用

```sh
./anettrace --perfetto-events tcp.jsonl --uid 10187 --trace tcp --proto tcp --duration 20
./anettrace --perfetto-events udp.jsonl --uid 10187 --trace udp --proto udp --duration 20
```

按应用采集系统与网络的合并轨迹：

```sh
./anettrace --capture-trace --uid 10187 --duration 20 --output app.pftrace
```

## 验证与使用边界

修复代码通过 GitHub Actions Linux/Android 编译与回归测试。OPPO PKC130 / 6.6.118-android15 真机验证默认配置、显式 TCP/UDP 分组及 `--force` 配置均能生成发送标记；转换后与原生 Perfetto 文件中的 flow ID 也已核验。验证使用受控回环负载，其他内核仍需实测。

`--force` 仅放宽部分抓取范围检查，不会取消已指定的 UID/PID 过滤。`--pid` 仍为精确线程 ID；`--trace` 选择探针，按协议过滤请同时使用 `--proto tcp` 或 `--proto udp`。
