# Anettrace v0.7.0

## 更新内容

- Perfetto 采集和 flow 导出开放普通 UDP 端口，修正 UDP 被误标为 DNS 的名称。
- TCP/UDP 协议调用独立显示起止时间、返回值；没有 flow 时也保留时间片。
- 增加 sendmmsg/recvmmsg、socket read/write/readv/writev，以及 AArch32/i386/x32 网络系统调用识别。普通文件 I/O 不进入网络轨道；批量调用返回值按消息数显示。
- flow 实例区分 socket 代次、netns 与会话代次，允许关闭后复用五元组；IPv6 socket 端点完整导出。
- packet_id 使用被观测 skb 的生命周期编号，避免 IPv6 UDP 全流共用 ID、IPv4 IP ID 重复造成的串包。
- 增加 UDP socket 销毁、接收数据拷贝探针，并通过 io_id/call_id/packet_id 关联实际调用上下文。保留拷贝 offset、长度及 copy_attempt 证据；歧义流不再按最近活跃项猜测。
- UDP 对端会话空闲 30 秒时推断结束并标记 incomplete，socket 销毁和 trace 截断具有不同结束原因。
- GitHub CI 新增普通 UDP trace 与文件式 socket I/O 的运行验证，以及身份、歧义和转换回归测试。

## 快速使用

```sh
./anettrace --capture-trace --uid 10187 --duration 20 --output game.pftrace
./anettrace --capture-trace --trace-detail --uid 10187 --duration 20 --output game-detail.pftrace
```

展开应用线程下的 Network syscalls，查看系统调用时间片；使用 packet_id、io_id、call_id 和 flow_id 搜索各层关联事件。抓取应在应用建立连接前开始，以观察 socket 创建。

## 时间与关联语义

- 系统调用进入/返回对应内核边界，不是 libc 用户态入口，也不表示实际无线发射或对端收到。
- receive_release 关联 UDP 接收后的缓冲释放（包括内联拷贝路径），不是拷贝入口；对应读取结果以 recv 返回值为准。
- copy_attempt 是数据拷贝入口证据，成功读取以 recv 返回值为准。MSG_PEEK、截断读取和一个调用涉及多个包时，不按一包一次调用假定。
- packet_id 表示观测到的 skb 实例。缓冲 head 替换、克隆、GSO/GRO、分片、重传和驱动/硬件卸载可能产生多个实例或不可见阶段；本版本不宣称这些实例与线上物理包一一对应，也不伪造其父子关系。
- trace 中途开始、探针不可用、事件丢失、身份映射淘汰和跨 CPU 迟到事件可能导致未关联或不完整链路。具体覆盖取决于设备内核提供的探针。
- 原生输出与 JSONL 转换支持相同的 packet_io_link 事件。离线处理必须使用同版本 host tools。

按用户要求，修改后的 C/eBPF 编译和运行验证仅在 GitHub Actions 执行。
