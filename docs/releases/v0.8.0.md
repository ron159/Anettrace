# Anettrace v0.8.0

## 主要变化

- 完善 Perfetto 精简与详细两种网络显示模式，共用 socket、flow、skb 和收发调用关联字段。精简模式保留关键节点，`--trace-detail` 展开已注册且设备可挂载的网络路径探针。
- 增加 socket 数据就绪、接收队列尝试和应用拷贝/释放观测；通过 `packet_id`、`io_id`、`call_id` 串联已观测的包与收发调用，保留实际执行线程。
- 保留发送包在 IP 头形成前的提交上下文，修正 skb 地址复用、socket 关闭后的终止事件归属和跨系统调用的旧状态污染。
- 扩展网络系统调用记录，覆盖 socket 的 `read/write/readv/writev`、批量收发及支持的兼容 ABI；批量调用返回值按消息数解释。
- 主机工具包增加 `tools/perfetto_sql/network_chain.sql`，可按流、socket、包或调用 ID 查询关联事件；原生导出与 JSONL 转换使用一致的关联字段。

## 快速使用

在设备 root shell 中运行，将 UID 替换为目标应用的实际 UID：

```sh
./anettrace --capture-trace --uid 10187 --trace-profile sched \
  --duration 20 --output /data/local/tmp/network.pftrace

./anettrace --capture-trace --trace-detail --uid 10187 --trace-profile sched \
  --duration 20 --output /data/local/tmp/network-detail.pftrace
```

在 Perfetto 中搜索 `tcp-1` 等流标签或完整关联 ID。需要精确查询时，将主机工具包中的 `network_chain.sql` 粘贴到 SQL 页，把 `selection` 改为例如：

```sql
selection AS (SELECT 'flow_tag' AS seed_kind, 'tcp-1' AS seed_id),
```

`--trace-profile full/sched` 选择系统数据源，`--trace-detail` 控制网络详细程度；`--pid` 仍为精确线程 ID。

## 验证与使用边界

本次功能通过 Linux/Android CI，并在 Android 真机完成回环与 Wi-Fi、精简与详细、JSONL 与原生轨迹六组验证。394 次成功调用具有关联记录，178 条收包链跨执行上下文关联到接收返回；两份原生轨迹分别完整导入 168 和 2398 个事件，未发现丢失事件或 Trace Processor 错误。这些结果来自受控负载，不代表任意设备或流量的完整覆盖。

精简 Wi-Fi 测试中，18 次 TCP 发送有 6 次仅保留提交证据，没有同一 `packet_id` 的后续发送路径；对应详细测试的 18 次均观测到发送关联。TCP 合并写入、skb 克隆、GRO/GSO、缓冲替换和未挂载探针仍可能造成链路断点，`packet_id` 表示观测到的 skb 实例，不等同于物理线上一个包。

socket 数据就绪回调不能单独证明某个包唤醒了某个应用线程；调度唤醒需结合系统调度事件分析。拷贝入口表示尝试，实际读取结果以系统调用返回值为准。UID/PID 过滤在早期收包尚未识别 socket 归属时可能漏掉事件；详细模式也不包含任意内核函数或硬件卸载阶段。
