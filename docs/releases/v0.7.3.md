# Anettrace v0.7.3

## 主要变化

- 修复 Android 上启用 `--trace tcp` 时 TCP reset 探针因累计栈占用超过 512 字节而无法加载的问题。三个 reset 探针现在只读取所需的 socket 状态字段，避免复制整个 `sock_common`。
- 真机回归脚本新增 TCP 拒绝连接场景，检查 `tcp_v4_send_reset` 实际包事件，覆盖默认采集未启用的探针。

## 快速使用

```sh
./anettrace --capture-trace --uid 10187 --duration 20 --output game.pftrace
```

## 验证与使用边界

修复已通过 GitHub Actions Android/Linux 编译，并在 OPPO PKC130 / 6.6.118-android15 真机验证：

- UID 2000 的受控 TCP 回环流量产生 37 条包事件，错误 UID 为 0。
- 精确 PID 的 TCP/UDP 流量分别产生 5/3 条包事件，错误 PID 均为 0。
- compact、detailed 和 TCP reset 真机回归全部通过。

`--pid` 保留精确线程 ID 语义，不包含该进程的其他线程；按应用采集可使用 `--uid`。上述验证使用受控回环负载，其他设备内核仍需实测。
