# Anettrace v0.5.0

本版本新增 Android TCP 主动建连根因诊断 v1。它面向已取得 root ADB shell 的系统、网络和性能
工程师，不要求修改目标应用，也不采集应用层内容。

## 主要变化

- 以单次 `connect()` attempt 为单位，关联 syscall、Socket 状态、RST、重传、内核 drop、RTT 和
  调度证据；
- 对 blocking 与 nonblocking connect 给出 `success`、`local_rejection`、
  `network_unreachable`、`peer_refused`、`timeout_no_response`、`kernel_drop`、
  `interrupted_or_cancelled` 或 `incomplete_or_unknown`；
- 通过 `direct`、`correlated`、`insufficient` 明示证据强度，证据不足时不猜测；
- 新增一键主机编排器、公开 JSON Schema、稳定 Trace Processor SQL 和 Perfetto 下钻时间线；
- Release 同时提供可复验 success/refused/timeout 与 30 分钟 soak 的静态 AArch64 workload；
- 产品版本、CLI、artifact、tag 和 manifest 统一使用 `0.5.0`。

## 快速使用

```sh
python3 tools/diagnose_android_connect.py \
  --package com.example.app \
  --binary /path/to/anettrace-0.5.0-android-arm64-dual \
  --trace-processor /path/to/trace_processor_shell \
  --out /path/to/report
```

默认采集 120 秒，使用 `sched` profile，并将报告限制为 512 MiB。设备端同时执行独立的时长和
文件大小限制。完整说明见 `docs/connect-diagnostics.md`。

## 支持范围与能力门控

- 目标范围为 Android 15+，但版本号本身不代表支持；工具会在启动前检查 root、BTF、tracefs、
  Perfetto、raw syscall tracepoint、KPROBE 和所需稳定 tracepoint；
- 已验证参考设备为 PKC130、Android 17 / SDK 37、AArch64 Linux 6.6.118；
- 参考设备使用 master dual backend 的 raw syscall、KPROBE/KRETPROBE 和 tracepoint 路径，
  不依赖完整 fentry/fexit；
- 核心能力缺失生成 `invalid` 报告，可选证据缺失生成 `degraded` 报告。

## 隐私

报告默认包含诊断所需的 IP、端口、UID/TID、匿名 Socket ID 和时间信息，因此分享前应检查。
默认不持久化包名、shared UID 候选、设备序列号或 fingerprint；只有显式指定
`--include-package` 才会写入包名。该版本不会读取 payload、URL、Header、SNI 或 DNS 内容。

## 已知限制

- 只诊断 TCP 主动建连，不覆盖 DNS transaction、QUIC/HTTP3 或已连接后的 HTTP/RPC 时延；
- 不提供 Linux 预编译二进制；Linux 继续从源码构建；
- Android 设备和厂商内核能力不同，除 PKC130 外均须以 preflight 和 attach smoke 为准；
- 首版不设置“慢连接”阈值，仅报告观测值；
- `android-tracing` 是独立实验产品线，本版本没有将该功能移植过去。

从现有 `0.4.0` 构建升级无需迁移已有配置；新诊断入口为显式 opt-in，现有 `--trace`、`--traffic` 和
`--capture-trace` 默认行为保持不变。
