# Anettrace v0.6.7

## 主要变化

- 修复流量概览中未连接 UDP socket 的地址显示为 `0.0.0.0`、远端端口为零的问题。
- 发送侧从路由信息获取实际端点，接收侧从数据报头获取端点，同一 socket 的多个目标分别统计。
- 覆盖 IPv4、IPv6、IPv4-mapped IPv6，以及未请求来源地址的 `recv()`。
- 保持成功 `sendmsg/recvmsg` 返回的应用层字节统计口径，包括短读取和 `MSG_PEEK`；失败调用不累计。
- 仅在启用 UDP 流量统计时挂载三个额外的端点探针，不复制数据包载荷，也不逐包输出事件。
- 特殊路径（例如尚未发送的 UDP cork/`MSG_MORE`）未取得端点时，以 `?` 展示并提示，保留字节数。
- 无法挂载必要的 UDP 端点探针时明确报错；依赖内核提供可探测的
  `udp_send_skb`、`udp_v6_send_skb`（IPv6）和 `skb_consume_udp`。

新增 Linux 真内核回归测试，检查多目标端点、双向字节数、IPv6、IPv4 映射、
连接后覆盖目标、`recv()`、`MSG_PEEK`、短读取和失败接收。
额外开销来自端点探针、固定长度元数据读取和已有流表操作，不承诺零性能开销。

## 快速使用

```sh
./anettrace --traffic --proto udp --interval 1
./anettrace --traffic --proto udp --uid 10123 --interval 1
```

需要 root 和 BTF 支持。`LADDR:PORT` 为本地端点，`RADDR:PORT` 为远端端点；
`APP_TX_KB`、`APP_RX_KB` 是应用层累计字节数，不包含 IP/UDP 头。
